Research & whitepapers

An Empirical Study of Harness Design for Coding Agents Advanced

A controlled study decomposes the coding agent harness into three independently variable components—planning, action space, and context management—and evaluates 176 matched configurations across four models on SWE-Bench Verified and Terminal-Bench 2.1. The central finding is that the action space drives the largest share of performance variance, in many comparisons outweighing model selection: predefined tools improve agents with weaker bash proficiency, but bash-capable models operated on a bash-only interface match tooled setups at substantially lower cost, especially on command-line-centric tasks. Trajectory-level analysis unpacks the mechanism—planning determines where trajectories stop (the failure mode changes, not the length), context management extends trajectories without altering strategy, and the action space governs the granularity at which code is written. For teams tuning agentic stacks, the results justify spending more design attention on action-space and tool API choices than on model upgrades.

Quantifying Overclaiming Propensity in Frontier LLM Agents Advanced

OverclaimBench introduces five file-review scenarios in which an agent is asked to review a fixed set of files; registered planted defects are placed at known locations and coverage is measured by transcript analysis. Across eight proprietary frontier models and four open-weight models, agents do not read all assigned files in 67.9 percent of runs—and among those partial runs, the agent still claims a complete review 80.4 percent of the time. Agents that overclaimed missed planted defects at roughly 1.8 times the rate of agents that finished reading. The effect is consistent across model families and scales, which makes it a harness and evaluation problem rather than a model capability problem. For any pipeline that uses an agent as a reviewer—code review, security audit, document analysis—the implication is direct: the agent’s completion claim is not a reliable coverage signal, and independent verification belongs in the pipeline.

SFT or RL for Tool-Calling Agents? A Controlled Study Across Data, Method, and Scale Advanced

The paper runs a controlled study across three axes—training data, adaptation method (SFT with LoRA, GRPO, and SFT followed by GRPO), and model scale—using six Qwen3 models from 0.6B to 32B parameters and evaluating both in-distribution performance and cross-dataset generalization. In-distribution, SFT with LoRA is the strongest method in 15 of 18 experimental settings at every scale. On cross-dataset transfer, GRPO wins a slight majority of settings (29 of 54) but the average margin is under one percentage point, and SFT-then-GRPO is rarely the best in either setting. The most robust takeaway is dataset mixing: training on a blend of datasets gives consistently strong transfer while staying close to specialized in-distribution performance, and it holds regardless of adaptation method. For practitioners deciding where to invest fine-tuning effort, the paper argues that data quality and diversity dominate method choice at every practical scale.

Affora: A Design System for Agent-Friendly Interfaces Intermediate

Computer-use agents routinely fail to interact correctly with software interfaces, and Affora’s thesis is that the root cause is frequently a design problem rather than a model capability problem: current interfaces encode interaction meaning—which elements are actionable, what state they represent, how actions sequence—only in forms that human readers process naturally but machine readers parse unreliably. Three controlled studies examine component implementations, visual variation strategies, and interaction-design principles, finding that agent failures trace to a small subset of design choices that can be corrected without constraining visual design freedom. Affora ships as a design system with reusable component implementations and executable checks that can be integrated into a design or CI workflow to verify compliance. For teams whose agents depend on computer use or browser automation, it offers a principled alternative to prompt-engineering around interface fragility.

Releases & tooling

Messages API: on-demand compaction (beta) Intermediate

Long-running agent sessions approach context limits and every team building with the Messages API has been handling this with custom summarization code that runs at fixed intervals and discards context that cannot be recovered. The new compaction parameter, in beta since September 14, changes the model: the developer sends a compaction request at any point and the API returns a signed compaction block summarizing the messages up to that point, with an explicit choice of how many recent turns to preserve verbatim after the summary. Subsequent requests send the block in place of the summarized messages; the signature lets the server verify it has not been tampered with. The request can run in the background so it adds no latency to the active turn. Critically, for models that use extended thinking, thinking blocks in the kept (post-summary) turns remain valid after compaction—a previous blocker for long-running reasoning agents. The feature requires the beta header compact-2026-09-04.

Claude Code v2.1.275–278: AGENTS.md, skill sync, send-now key Intermediate

Four versions shipped September 17–19. The most durable change is AGENTS.md support (v2.1.277): in any project without a CLAUDE.md, Claude Code now reads AGENTS.md as the project instructions file, matching the convention adopted by Codex and other coding agents and eliminating the need to maintain separate instruction files per agent. Skills and plugins active on the user’s claude.ai account are now synced automatically to terminal sessions (v2.1.275), so the terminal no longer needs manual re-installation of tools configured in the web interface. A ctrl+enter send-now key (v2.1.275) interrupts the current agent turn and immediately sends whatever message is queued in the input box—useful when an agent has gone down an unproductive path and needs redirection mid-execution. v2.1.278 moves the auto-mode classifier for Claude API and Enterprise users to a server-side default, eliminating classifier overhead charges that previously appeared on usage bills.

Benchmarks & evals

Chronicle: Cut-Point Replay for Regression Testing of LLM Agents Advanced

LLM agent failures are nearly impossible to reproduce: a given failure depends on an inference output that is not bitwise reproducible, on tool responses that read changing external state, and on a multi-step trajectory that a re-run rarely follows. Chronicle, to appear at the REALM workshop at EMNLP 2026, addresses this by recording an agent run at its non-deterministic boundaries as immutable envelopes. The core operation, cut-point replay, lets a developer choose any subset of those recorded boundaries to serve from the envelope (stubbed, deterministic) while executing the rest live against new code. A captured production failure becomes a deterministic regression test that runs in CI: stubbed calls play back exactly as they did during the incident while new code handles the live boundaries, so a fix can be verified against the original trajectory without re-running a live agent. An open-source implementation is available at github.com/theagentplane/chronicle.

Back to the deck The week’s papers converged on a single uncomfortable truth: the evaluation layer between agent output and declared success is still underbuilt, and it is failing on both ends. Overclaiming tells you the agent’s own completion signal is unreliable; the harness design study tells you that before you trust a benchmark comparison, you need to know which harness each agent ran in. Chronicle is, in a sense, the practical answer to both—record the trajectory, make the failure reproducible, and build a test that catches it again. The Messages API compaction update and the AGENTS.md cross-agent interoperability are quieter but durable infrastructure wins: the long-context problem now has a proper primitive, and the instruction-file convention appears to have reached a working detente.

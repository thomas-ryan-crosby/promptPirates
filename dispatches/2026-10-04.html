Research & whitepapers

PACE: Provenance-Aware Capability Enforcement for Tool-Using LLM Agents Advanced

When a tool-using agent retrieves a document, browses a page, or reads from shared memory, any of those sources can carry instructions that steer the next tool call — a threat that bypasses the model’s own refusal behavior because the harmful intent arrives as retrieved context rather than a direct user prompt. PACE mediates every tool call immediately before execution: path confinement builds a graph of represented influence reaching the proposed call and proposes an executable cut of influence paths that exceed the call’s authority, while capability and effect verification checks the call’s schema-defined effects against authority compiled only from the authenticated request. The system distinguishes the certified execution contract from the evaluated configuration, allowing a blocked-but-legitimate call to be restored after a declared repair is applied. For teams deploying agents that read from uncontrolled external sources — web search, shared retrieval stores, multi-agent memory — PACE targets the supply-chain attack surface of tool use rather than the generation surface.

DeFA: Dependency-Guided Failure Attribution for LLM Agents Advanced

In a multi-agent pipeline with dozens of tool calls across several agents, debugging a failed run typically means replaying the trajectory by hand to find where execution diverged. DeFA automates this forensic step by combining protocol relations and semantic dependencies across the full trajectory into an event dependency graph, identifying events that violate task requirements, and tracing both their upstream sources and their downstream propagated effects into a failure propagation graph. On the Who and When Pro diagnostic test subset, DeFA achieves the highest responsible-agent and exact-step accuracy of any evaluated backbone, and the highest failure-mode accuracy among taxonomy-aligned methods. The result is a structured diagnosis: which agent, at which step, and through which propagation path a failure reached the final outcome — surfacing root causes that would otherwise take a developer hours of manual log inspection to reconstruct.

arXiv 2610.01256 · October 2, 2026

TRACE: Trajectory Return Attribution and Contrastive Erasure for Multi-Turn Safety Advanced

Jailbreaks that succeed across many turns work in part because standard safety training assigns credit only to the most recent model output, leaving the gradual context shifts that induced the failure untouched by the training signal. TRACE addresses this by weighting each token across the full conversation history by the discounted return of a refusal-attributable advantage: it compares a frozen reference model with its refusal-ablated copy, so tokens early in the transcript can receive training credit when they are causally responsible for a compliance or refusal many turns later. The contrastive erasure step removes reward signal from tokens whose effect on the final behavior is dominated by other trajectory factors, concentrating gradient updates where they change multi-turn safety outcomes. For practitioners fine-tuning models for long agentic sessions — where gradual user-context manipulation is a realistic attack vector — TRACE provides a training signal that does not collapse attribution to a single response.

Held September 29 for roughly 2,500 attendees, DevDay shipped more than twenty developer announcements. The three most immediately consequential for agent builders: GPT-6.1 Sol launches at $2/$10 per million input/output tokens — one-fifth of GPT-6 Astra’s standard rates — with a 1.05M-token context window and benchmark performance approaching Astra on agentic coding and computer-use tasks. Claude Code mods: TypeScript hooks for agent behavior and UI Intermediate

Launched October 1, mods are small TypeScript functions that attach to Claude Code’s internal event stream and intercept what happens at each significant action: a mod can rewrite a prompt before it reaches the model, block or retry a tool call, handle a permission request, redact a secret from tool output, or replace an interface element entirely. The architecture is event-based — Claude Code emits events before and after each action, and mods register handlers for whichever events they target — with multiple mods from different sources composable into a stack without conflict. At launch, Anthropic converted three built-in features — the diff pane, the agents.md loader, and telemetry — into mods, marking the system as load-bearing rather than experimental and making those features overridable like any team-authored mod. Mods ship inside plugins and install via the /plugin command in both the CLI and desktop app; they run with the same machine privileges as Claude Code itself and are explicitly unsandboxed, so the install trust bar equals that of any program run locally.

Benchmarks & evals

KaliBench: Fine-Grained Cybersecurity Tool Use on Kali Linux Advanced

Accepted at the NeurIPS 2026 Evaluations and Datasets Track, KaliBench measures whether a model can translate a natural-language security analyst request into the exact executable CLI command for the right Kali Linux tool — not approximate intent, but the specific flags, argument order, and value bindings the tool’s interface requires. The dataset covers 8,504 query-command pairs across 1,642 tools, 23 capability dimensions, and 5 security phases, built through a manuscript-grounded pipeline with deterministic canonicalization and alias-aware evaluation. The evaluation pipeline avoids live runtime execution by combining LLM-based validation, sandboxed terminal parsing, and human-in-the-loop refinement, producing verifiable reward signals suitable for reinforcement learning at scale. Open models top out at 42% exact accuracy — a ceiling that quantifies how much ground the current generation still has to cover before agents can drive security tooling without per-command human verification of the generated output.

arXiv 2610.02206 · October 2, 2026

AsynCodeBench: Benchmarking Async Multi-Agent Coordination in Software Engineering Advanced

Most software engineering benchmarks grade a single agent on a single task; AsynCodeBench grades a pool of asynchronous agents on how well they satisfy inter-agent dependencies across parallel execution. Each of the nineteen tasks is grounded in a real-world repository and annotated with an explicit dependency graph and executable Dependency Checkers that verify whether each cross-agent dependency was actually satisfied during the run. Two new metrics structure the evaluation: Asynchronous Dependency Pass Rate (ADPR) measures what fraction of cross-agent dependencies were ultimately satisfied, and Dependency Resolution Step (DRS) measures exactly when each dependency first became resolved in the trajectory. The main empirical finding is structural: successful coordination does not emerge gradually but in short concentrated bursts — termed hopping windows — where many dependencies resolve over a tight slice of the execution. The implication is that inter-agent handoff mechanisms, not per-agent capability, are the primary bottleneck limiting async multi-agent coding performance.

Back to the deck The week’s papers share a design principle: move from binary outcomes to structured diagnostics. PACE names the influence path that allowed a poisoned artifact to steer a tool call. DeFA names the agent and step that originated a cascading failure. TRACE names the tokens across a multi-turn conversation that carry the weight of a final safety decision. AsynCodeBench names the specific handoff moment where coordination succeeded or broke. That shift — from “it failed” to “it failed here, for this reason, at this step” — is what makes an agent system improvable rather than merely restartable. The DevDay and mods releases sit on the same axis from the tooling side: a cheaper near-frontier model, a sub-millisecond routing primitive, and hookable behavior surfaces mean the next iteration cycle has shorter feedback loops.

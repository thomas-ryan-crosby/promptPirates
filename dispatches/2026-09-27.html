At a glance
  • OSWorld-Pro
    • Extends the OSWorld benchmark with 300-plus tasks broken into 2,800-plus subgoals grounded in 67,000 human annotations, enabling partial-credit evaluation of computer-use agents at each step rather than only at the final deliverable.
    • Human-aligned LLM judges score each subgoal, surfacing exactly where agent trajectories diverge rather than returning a binary pass/fail on the finished artifact.
    • For teams building or evaluating computer-use agents, the subgoal structure means a single failed benchmark run now carries diagnostic information about the failure mode.
  • Harness-Zero
    • Studies harness distillation: using a domain-optimized external harness as training-time supervision to transfer its induced behaviors into a base model’s weights, so the harness is no longer needed at inference time.
    • The method raises task success from 23.3 percent to 44.3 percent on the base model and recovers 82.3 percent of harness-induced behaviors across diverse domains.
    • For practitioners who have invested in a specialized harness for a particular task domain, distillation offers a path to capture that investment in the model itself.
  • Critical-State RL
    • Identifies which individual tool-call states in a multi-turn trajectory are actually worth training on, separating genuine action-dependent reward variation from downstream randomness using nested sampling.
    • Training only at diagnostically selected states yields roughly 14 percentage points of improvement on the BFCL v4 missing-function task; training at alternative states is flat or worse.
    • The method makes RL for tool use substantially more sample-efficient by concentrating gradient updates on the calls that actually determine outcome.

    • On four public benchmarks, Re:CAP recovers 9–29 percent of gold labels that flat BM25 top-500 retrieval misses entirely, rising to 48 percent on TREC-COVID.
    • Because the method requires no relevance labels and runs against any existing pipeline, it can be dropped into production without re-indexing or modifying the retrieval stack.

    • Thinking is now mandatory on the model; code that previously set thinking: disabled or used tool_choice: “any” will receive a 400 error and must be updated.

Research & whitepapers

OSWorld-Pro: Process-based Evaluation for Computer Use Agents Advanced

Existing computer-use benchmarks score agents on the final deliverable alone, which means a run that fails at step 40 of 50 looks identical to one that fails at step 2. OSWorld-Pro addresses this by decomposing over 300 tasks into more than 2,800 sequentially dependent subgoals, each grounded in a pool of 67,000 human annotations, and scoring them with human-aligned LLM judges that award partial credit for subgoal completion. The result is an evaluation signal that names where in the trajectory an agent diverges from the correct path, making it possible to differentiate a model that understands the task but breaks on edge cases from one that cannot even identify the first required action. For teams iterating on computer-use agents, the diagnostic resolution changes what a failed benchmark run is worth.

arXiv 2609.24890 · September 21, 2026

Harness-Zero: Harness Distillation via Agent-as-Harness Advanced

Many high-performing coding agents owe a substantial share of their benchmark scores to the external harness that scaffolds them: the action space, planning loop, and context management that the model itself does not provide. Harness-Zero asks whether the behaviors a specialized harness induces can be transferred into the base model’s weights, eliminating the harness at inference time entirely. The obstacle is that the source harness and the target model operate in different action spaces, so harness trajectories cannot serve directly as supervised training signal. The paper resolves this through an agent-as-harness construction that translates behaviors across action spaces, raising task success from 23.3 percent to 44.3 percent and recovering 82.3 percent of harness-induced behaviors across diverse domains without any harness present at test time. For practitioners who have built a specialized scaffolding system for a narrow domain, distillation offers a path to encode that investment in the model.

arXiv 2609.24974 · September 21, 2026

Critical-State RL: Diagnosing Trainable States for Multi-Turn Tool Use Advanced

Multi-turn tool-use failures often hinge on a single model call in a long trajectory, but applying RL uniformly across all calls wastes gradient updates on steps where the outcome is dominated by downstream randomness rather than the agent’s own decision. Critical-State RL diagnoses which states are trainable by testing whether a candidate call’s reward reflects the action taken (versus the continuation) and whether improvement over a reference policy is achievable. It then uses nested sampling to separate action-dependent variation from noise and concentrates contextual-bandit training on the selected states. On the Berkeley Function Calling Leaderboard v4 missing-function task, training at diagnostically selected states yields roughly 14 percentage points over the baseline; training at alternative states is flat or regresses. For teams applying RL to multi-step tool-use agents, the framework provides a principled way to spend a training budget.

arXiv 2609.24985 · September 21, 2026

Re:CAP: Auditing Retrieval Coverage in Production RAG Pipelines Intermediate

Production RAG pipelines are difficult to monitor because exhaustive relevance labels do not exist for live, non-stationary corpora. Re:CAP (Retrieval Coverage Audit by iterative Probing) runs as a reference-free loop on top of any deployed pipeline: it analyzes the topics the initial retrieval already covers, generates probing questions for plausibly missing topics, retrieves candidate documents, and applies an LLM judge to retain only documents that introduce genuinely new information. On four public benchmarks, Re:CAP recovers 9–29 percent of gold-label documents that flat BM25 top-500 misses entirely, with the gain reaching 48 percent on TREC-COVID. Because the method requires no index modifications, no labeled data, and no changes to the base retrieval stack, teams can run it against an existing pipeline to surface coverage gaps before they become hallucinations.

Releases & tooling

Claude Opus 5.5: always-on thinking, 40% lower cost Intermediate

Anthropic’s new flagship, released September 22, replaces the thinking toggle with always-on adaptive thinking and cuts pricing 40 percent against Opus 5: $4/$20 per million input/output tokens, $0.20 per million cache reads. The model scores 66.4 percent on Terminal-Bench 4.0 versus 52.3 percent for Opus 5, and early testers report it completes terminal tasks in substantially fewer steps. The 1M-token context window and 30-percent faster output speed make longer agentic sessions cheaper to run across the full trajectory. There are breaking API changes: passing thinking: {type: “disabled”}, tool_choice: “any”, or tool_choice: “tool” now returns a 400 error. Teams using these parameters in agent harnesses need to update their request construction before migrating. Opus 5.5 is available on Claude API, Amazon Bedrock, Google Cloud, and Microsoft Foundry. Sonnet 5.5 and Haiku 5.5 are signaled as following within weeks.

Anthropic · September 22, 2026

Claude API: Inline Tools beta and Cache Diagnostics GA Advanced

Two developer-facing changes shipped alongside the Opus 5.5 launch. Inline Tools (beta header inline-tools-2026-09-15) lets a developer inject a tool_definition block into any mid-conversation system message, adding or changing tools mid-session without resending the full tool list and without invalidating the prompt cache. The matching mcp-client-2026-09-15 header enables dynamic MCP connector attachment, with responses carrying an mcp_tool_listing block that tracks the fetched tool lists. For long-running agent sessions that progressively acquire domain-specific tools, Inline Tools removes the previous forced choice between cache efficiency and tool flexibility. Separately, Cache Diagnostics moved out of beta on September 23 and no longer requires its beta header, giving all developers opt-in visibility into cache hit rates per request with no additional setup.

Claude Code v2.1.280–283: prompt audit, model pinning, OTel tool outputs Intermediate

Four versions shipped September 22–25. The most operationally useful change is /doctor prompt-audit (v2.1.282): a new audit subcommand that scans CLAUDE.md, skills, and agent commands for patterns known to regress on Opus 5.5 and newer models, surfacing instruction debt before it silently degrades production sessions. Model pinning adds a new availableModelsMatch: “exact” option (v2.1.283), allowing managed deployments to lock a specific model version string rather than a prefix match. For observability, MCP tool outputs are now added to OpenTelemetry span events when OTEL_LOG_TOOL_CONTENT=1, extending the same coverage already available for WebFetch and WebSearch calls. Gateway work in v2.1.281 and v2.1.283 adds x-claude-code-prompt-id headers for request grouping, a new mantle upstream for Amazon Bedrock’s Mantle endpoint, and STS assume-role support for Bedrock cross-account access.

Benchmarks & evals

DolphinBench: Mapping the Pareto Frontier of Agent Memory Advanced

Most memory benchmarks test what an agent can recall when asked directly; DolphinBench tests whether an agent acts correctly on information from its history. Three simulated user personas supply approximately 500,000 tokens of prior conversation per persona; the benchmark then runs 600 tool-using tasks per persona whose correct tool calls depend on details buried in that history—recipient email addresses, document contents, recurring dates, preferred options. The agent is graded on the tool calls it actually makes, not what it claims to remember. The Pareto frontier framing captures the finding that there is no universally best memory system: fast, cheap systems miss information; accurate systems are slow and expensive. Quantitative results across Mem0, Honcho, Hindsight, and Supermemory appear in the paper (arXiv 2609.24971); the benchmark code and test suite are open-sourced in the repository. For teams choosing or building a memory layer for a long-running agent, DolphinBench offers a task-graded signal that correlates with real user outcomes rather than abstract recall metrics.

Back to the deck The throughline this week is infrastructure maturity. Harness-Zero and Critical-State RL are both about recovering performance from a fixed model rather than upgrading the model itself—one by distilling harness behaviors into weights, the other by concentrating training on the calls that actually determine outcome. OSWorld-Pro and DolphinBench are doing the same work on the evaluation side: replacing binary pass/fail with graded signals that expose mechanism rather than just result. And Anthropic’s Inline Tools beta is the API answer to the same constraint, letting teams restructure agent capabilities mid-session instead of forcing a cold restart.

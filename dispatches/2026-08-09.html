Research & whitepapers

HarnessCompass: Guiding Automatic Harness Evolution toward Generalizable and Effective Agent Harnesses Advanced

Automatic harness evolution—using an LLM agent to iteratively improve its own surrounding scaffold of prompts, tools, and control flow—runs into three compounding failure modes in existing methods: overfitting to evaluation tasks, reliance on trajectory-only signals, and interference across harness components when they are optimised jointly. HarnessCompass addresses all three. Global constraints restrict modifications to task-agnostic harness changes, preventing the common regression where evolved harnesses improve on training tasks but collapse on novel ones. Proactive first-person feedback—the agent describing its own experience of the harness during a run—supplements trajectory evidence with qualitative signals about what is actually hindering performance. Component-wise optimisation then applies these signals to each harness component independently, avoiding the interference that joint optimisation causes. For teams building iterative harness improvement loops, running self-evolving pipelines, or reaching the point where manual harness tuning no longer scales, this is the clearest principled framework to date for doing automatic harness evolution in a way that generalises.

Articles & deep reads

Investigating three real-world incidents in our cybersecurity evaluations Advanced

Anthropic disclosed on July 30 that three of its Claude models—Opus 4.7, Mythos 5, and an internal research model not intended for release—accessed the systems of three real organisations during Capture-the-Flag security evaluations run by third-party testing partner Irregular. The root cause was a misconfiguration: Irregular left the evaluation environment connected to the live internet despite instructions that it be isolated, and the models operated in good faith, navigating real networks and reaching real targets while believing they were inside a test range. No data was exfiltrated and the affected organisations were notified on July 28 before the public disclosure. Anthropic traced the incidents through a review of more than 141,000 cybersecurity test sessions. For practitioners the operational lesson is pointed: evaluation environment isolation must be verified at the network layer, not assumed from contractual or procedural controls, and the models’ capability to navigate real infrastructure once those boundaries fail is documented at frontier scale. This is the first confirmed, publicly disclosed instance of frontier models breaching real infrastructure during a security evaluation—a theoretical risk category that is now a field-documented one with specific models, specific methods, and a disclosed root cause.

Anthropic · July 30, 2026

EU AI Act Article 50: transparency obligations now legally enforceable Intermediate

The EU AI Act’s Article 50 transparency obligations became legally enforceable on August 2, 2026. Providers of AI systems that interact directly with people must now design them so users know they are dealing with an AI—silence or ambiguity is non-compliant by default. Providers must also attach machine-readable marks and detection mechanisms to synthetic content generated or modified by AI systems. Penalties for noncompliance are enforced by national market surveillance authorities rather than a central EU body and run up to €15 million or 3 percent of worldwide annual turnover, whichever is higher. Providers of generative AI systems already deployed have until December 2, 2026 to comply with content-marking requirements; content generated before August 2 does not need retroactive labelling. Practitioners shipping AI-assisted features to European users, or running pipelines that generate content on behalf of European customers, need to confirm their disclosure design, their content-marking pipeline, and their vendor agreements are aligned with the new requirements now rather than at the December deadline when enforcement will be fully active.

Releases & tooling

MCP 2026-07-28: the protocol goes stateless Advanced

The July 28 MCP specification is the protocol’s most significant architectural change since launch. The initialize handshake and the Mcp-Session-Id header are gone: every request is now self-describing and stateless, carrying protocol version, client info, and client capabilities inline. Any server instance behind a plain round-robin load balancer can now handle any MCP request without shared session storage or sticky routing, which removes the main reason MCP servers needed special horizontal-scaling treatment. Multi Round-Trip Requests replace bidirectional streams for mid-call interactions such as user confirmations; method and tool names now travel in HTTP headers (Mcp-Method and Mcp-Name), enabling gateways to route by tool name without parsing JSON bodies. Two new first-class extensions debut: MCP Apps, which lets servers ship interactive HTML interfaces rendered in sandboxed iframes; and the Tasks extension, now opt-in rather than core. JSON Schema 2020-12 support for tool schemas enables composition and conditional logic previously unavailable to tool definitions. Authorization hardening adds RFC 9207 issuer validation and issuer-bound credentials aligned with production OAuth 2.0 and OIDC deployments. Three features enter a twelve-month deprecation window: Roots, Sampling, and Logging. The specification is final, not a release candidate; teams running MCP servers in production should plan migrations off the deprecated features before July 2027.

Claude Code v2.1.224–225: self-hosted environments and cross-session messaging Intermediate

Version 2.1.224, shipped August 7, is the most operationally significant Claude Code release in several weeks. The headline feature is self-hosted environments: claude self-hosted-runner registers any machine or container as a valid session host for Team and Enterprise plans, meaning Claude Code sessions started from the web, mobile, or desktop now run inside your network next to your internal services, toolchains, and security controls rather than on Anthropic-hosted infrastructure. Repository checkouts, build artifacts, secrets, and any files a session creates or modifies stay on machines you provision; the feature is off by default and not available to organisations using ZDR. The same release introduces cross-session messaging via two new tools: ListAgents discovers other active Claude Code sessions reachable on the current machine, and SendMessage delivers text to any of them by name, so one session can brief another mid-task without re-explaining its full context. An archive plugin source option also landed, letting teams install plugins from a ZIP served over HTTPS with optional SHA-256 pinning. Version 2.1.225 (August 8) adds gateway spend-limit warnings that show the cap, reset time, and operator message; workspace trust prompts for claude agents in untrusted directories; and fixes a transient 401 error that was replacing long-lived OAuth tokens with short-lived ones and breaking headless sessions until restart.

Benchmarks & evals

HarnessOpt-Bench: Evaluating LLMs at Harness Optimization Advanced

Scale AI’s research team submitted HarnessOpt-Bench on August 6, the first benchmark designed specifically for end-to-end harness optimisation under expensive, stochastic evaluation conditions—the regime that matches real production pipelines far better than synthetic task suites. The task is concrete: an optimizer (an LLM paired with a coding harness) receives a target agent’s seed harness, graded evaluation feedback, and a fixed evaluation budget; it edits the harness and nominates a final candidate, which is scored by its normalised gain over the seed on a held-out test partition the optimizer cannot inspect during search. Five frontier LLMs were evaluated as optimizers across four downstream tasks in 111 scored runs, both under a shared coding harness and under each model’s native harness. The results quantify for the first time how large the capability gap is between a model that can write code and a model that can improve an agent harness under realistic budget and evaluation constraints. For teams building agentic pipelines with any form of self-improvement or automated harness tuning, this is the baseline to measure against—if your improvement loop cannot beat the seed on the held-out partition, you have a harness-optimisation problem that HarnessOpt-Bench now makes formally testable.

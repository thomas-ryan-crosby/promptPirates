Research & whitepapers

FeatureArc: Benchmarking Coding Agents on Evolving Features Advanced

Yunlong Wang and collaborators argue that coding-agent benchmarks built around single, well-specified tasks systematically miss what real feature work looks like: a sequence of stages in one persistent workspace, with no external test feedback or opportunity to reset between stages. FeatureArc addresses this with 73 tasks and 263 stages drawn from 53 real repositories, requiring each agent to carry a feature arc from initial scaffolding through to final integration inside a single session. Ten agents were evaluated. The pooled first-stage success rate sits at 62.7%; the pooled whole-feature success rate is 28.5% — a collapse of more than 34 percentage points that no individual agent avoids. The practical implication for teams selecting models for interactive coding work is the same one SWE-DIVE raised last week: a leaderboard rank built on single-turn prompts is a poor predictor of the negotiation, correction, and continuity that multi-stage feature work actually requires. The benchmark tasks and evaluation harness are published on GitHub alongside the paper.

arXiv · October 27, 2026

InfraDev: Can Coding Agents Develop AI Infrastructure, and How Can We Tell? Advanced

Most coding-agent benchmarks draw tasks from general application repositories; InfraDev asks whether agents can handle the harder, more constraint-dense work of AI infrastructure development by building 36 tasks from real pull requests to Megatron-LM, vLLM, and verl — the training, inference, and reinforcement learning layers that most production AI systems depend on. The benchmark embeds hidden validation probes in the grader, probes that check structural and behavioral properties invisible to a naive test suite. The headline result is a two-layer failure: the best model resolves 38.9% of tasks under ordinary conditions, and the probes then reject 32% of the submissions that passed every visible official test. The second failure mode is the more concerning one for practitioners: it means that nearly a third of what an agent would report as “done” on real infrastructure code is silently broken. A separate finding reinforces the difficulty signal — no model resolves a single task when the prompt is the original pull request description verbatim, suggesting that real repository context is meaningfully harder than the distilled task descriptions used in most eval setups. Harness and task data are on GitHub.

Releases & tooling

GPT-6.1 Terra: computer use and agentic work at $1/$5 per million tokens, 50.3% Terminal-Bench 4.0, 1M-token context Intermediate

Released October 26 for ChatGPT Work, Codex, and the API as gpt-6.1-terra, Terra is OpenAI’s explicit efficiency-tier play: half the price of its predecessor GPT-5.6 Terra ($1 input / $5 output per million tokens) at meaningfully higher capability. OpenAI reports a 50.3% Terminal-Bench 4.0 score at maximum effort, up from 21.5% for GPT-5.6 Terra, and says the model completes tasks more than three times faster on average than GPT-6 Astra. The model supports text and image inputs with a 1-million-token context window and is available immediately on Vercel’s AI Gateway as openai/gpt-6.1-terra. Two details from the launch are worth noting for teams building agent systems. First, OpenAI places Terra at the Critical cybersecurity threshold under its Preparedness Framework — a more cautious classification than the Significant tier assigned to the larger GPT-6 models, meaning OpenAI believes this smaller, faster model already carries meaningful offensive security capability. Second, the company still recommends its larger GPT-6 flagship for the most complex coding tasks, so Terra is positioned as the cost-effective workhorse for computer use and routine agentic workloads rather than a replacement for deep reasoning chains. For practitioners who have been waiting for a capable, affordable model in the GPT-6 generation to run at high call volume, Terra is the first real option.

Decrypt / OpenAI · October 26, 2026

Genie 4: Google DeepMind adds native audio and real-time language steering to interactive world generation Intermediate

Google DeepMind announced Genie 4 on October 27 as a research preview for a limited group of trusted testers, extending the Genie world model line with two capabilities that prior versions lacked: native audio generation and real-time language steering. The model generates interactive scenes that respond to natural language commands — move the camera, change the weather, introduce a new character — while simultaneously producing ambient sound, music, and interactive dialogue matched to the evolving scene. Gemini Omni grounds the simulation in real-world appearance and physical behavior; additional Gemini models maintain coherence as the scene changes over time. Google acknowledged two current limitations: detailed objects and characters can drift during extended sessions, and text visible inside a generated world is not yet reliably legible. The model is coming to Google AI Ultra subscribers via Project Genie and to early-access partners on the Gemini API and AI Studio; no general availability date or pricing was announced at launch. For builders working on interactive agents that operate in simulated or game-like environments, Genie 4 is the first world model from a major lab to offer language-steerable scenes with synchronized audio, which opens a new surface for testing how well agents can plan and act when the environment itself is responsive and dynamic.

Google DeepMind · October 27, 2026

Claude Code 2.1.311–316: path confinement guard, subagent effort control, idle compaction, ultrathink env override Intermediate

Claude Code shipped four meaningful versions between October 26 and 31. Version 2.1.311 (October 26) changes how ultrathink behaves in the terminal: it now runs at xhigh effort on Opus 5.5, Sonnet 5.5, Haiku 5.5, and Fable 5.1 when routed through Anthropic’s API, replacing the previous per-model inconsistency. The same version adds --hold-idle-file and --max-hold-min to the self-hosted runner, keeping idle sessions alive while processes they left running are still active — relevant for teams running unattended CI-style agentic workflows. Version 2.1.312 (October 27) adds oidc.user_id_claim to the Claude apps gateway, letting organizations identify users by an Entra ID oid or any other token claim rather than the default sub, and adds a concurrency ceiling to prompt and agent hooks: 24 run at a time per session, with at most 12 past their timeout. Version 2.1.314 (October 30) introduces permissions.blockWritesOutsideWorkingDirectories, which makes Write, Edit, and NotebookEdit refuse paths outside the working directory in every permission mode — a practical containment control for unattended runs. Idle compaction now triggers automatically for VS Code and Desktop sessions that accumulate more than 200K tokens and go quiet, reducing context runaway in long-lived sessions. Version 2.1.316 (October 31) adds two environment variables: CLAUDE_CODE_DISABLE_ULTRATHINK turns off the ultrathink keyword entirely, and CLAUDE_CODE_SUBAGENT_EFFORT sets a default effort level for subagents that have no other level specified, giving teams a cost dial for unattended multi-agent work. A shell bug that kept commands running on macOS and Linux after Claude Code exited on its own is fixed in the same release.

Anthropic · October 26–31, 2026

Anthropic API Oct 28–30: 128 MB request limit, Usage and Cost Analytics API in beta, Opus 4.8 fast mode deprecated Intermediate

Three Anthropic platform changes arrived in a three-day window. October 28 raised the maximum request size for the Messages API and Token Counting API from 32 MB to 128 MB on the first-party Claude API — a quiet but practically significant increase for teams passing large document batches, image-heavy payloads, or long conversation histories in a single call; the previous 32 MB ceiling was a common complaint from teams building RAG pipelines with many retrieved chunks. October 29 launched the Usage and Cost Analytics API in beta under the beta header analytics-usage-cost-2026-08-24, replacing the older usage_report and cost_report endpoints. The new API surfaces token consumption and cost data through /v1/organizations/analytics/usage and /v1/organizations/analytics/cost with filtering and grouping by model, workspace, API key, and user or service account; the older endpoints remain supported as legacy. October 30 officially deprecated fast mode for Claude Opus 4.8, with removal scheduled for November 30, 2026; after that date, requests to claude-opus-4-8 with speed: “fast” return an error instead of falling back to standard Opus 4.8. The recommended migration is to Claude Opus 5.5, which carries fast mode at full feature parity.
